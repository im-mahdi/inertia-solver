# Inertia Solver — پروژه‌تمرین ۱ هوش مصنوعی

عامل جستجو برای معمای **Inertia** (مجموعه‌ی Simon Tatham). فقط به **Python 3.8+** نیاز دارد؛ هیچ کتابخانه‌ی خارجی لازم نیست.
(برای رابط گرافیکی `tkinter` لازم است؛ در ویندوز/مک همراه پایتون است، در لینوکس: `sudo apt install python3-tk`)

## فایل‌ها
| فایل | کار |
|---|---|
| `inertia_solver.py` | هسته: خواندن ورودی، الگوریتم‌ها، بررسی‌کننده‌ی مستقل، مقایسه، بنچمارک، CLI |
| `inertia_gui.py` | رابط گرافیکی (نمره‌ی اضافی): بازی دستی، تعریف معمای جدید، حل با عامل، بازپخش |
| `samples/` | نمونه‌ها (فایل ذخیره‌ی Tatham، شناسه‌ی بازی، شبکه‌ی متنی، حل‌ناپذیر) |
| `REPORT_fa.md` | پیش‌نویس گزارش ۳ صفحه‌ای (اعداد را با خروجی اجرای خودتان جایگزین کنید) |

## اجرا
```bash
python inertia_solver.py samples/sample_10x8.txt               # bfs + ids + A*  (پیش‌فرض)
python inertia_solver.py game.sav                               # فایل ذخیره‌ی خود معما (Game > Save download file)
python inertia_solver.py game.sav --algo all --tt --trace        # هر هفت الگوریتم + ردگیری مرحله‌به‌مرحله
python inertia_solver.py game.sav --algo bfs,astar --out sol.txt
python inertia_solver.py game.sav --check 8241874693268141       # بررسی خودکار یک دنباله از کنش‌ها
python inertia_solver.py --benchmark 10 --size 8x6 --algo bfs,ids,astar --tt --csv res.csv
python inertia_solver.py --selftest                              # آزمون‌های داخلی
python inertia_solver.py --gui                                   # رابط گرافیکی
```
(در لینوکس/مک اگر `python` نبود از `python3` استفاده کنید.)

## ورودی
هر کدام از این‌ها پذیرفته می‌شود (تشخیص خودکار):
1. **فایل ذخیره‌ی Tatham** (`SAVEFILE ... PARAMS ... DESC ...`) — بخش `DESC` خوانده می‌شود؛ هر سطر/ردیف به ترتیب سطری است.
2. **شناسه‌ی بازی** `10x8:mwbmss...` یا فقط رشته‌ی DESC.
3. **شبکه‌ی متنی چندخطی** (`. * X o # @` یا حروف `b g m s w S`).

حروف: `b` خالی، `g` الماس، `m` مین، `s` ایستگاه (دایره‌ی خط‌چین)، `w` دیوار، `S` شروع.
اگر ورودی خراب باشد پیام خطای روشن (کد خروج ۲) داده می‌شود، نه کرش.

## خروجی
وضعیت: **SOLVED** / **NO_SOLUTION** (فضای جستجو تمام شد) / **LIMIT** (محدودیت زمان/گره/حافظه).
توالی کنش‌ها با **ارقام صفحه‌کلید عددی** چاپ می‌شود: `7=NW 8=N 9=NE 4=W 6=E 1=SW 2=S 3=SE`
— همین ارقام را می‌توانید در بازی وب تایپ کنید تا راه‌حل را ببینید. صحت راه‌حل با یک شبیه‌ساز **مستقل** از کد جستجو بررسی و در ستون `Verified` گزارش می‌شود.

## جدول خروجی (واحدها طبق صورت پروژه)
`Expanded` = گره‌های گسترش‌یافته، `PeakNodes` = بیشینه‌ی گره‌های نگهداری‌شده در حافظه (واحد حافظه)، `Time(ms)` = فقط زمان جستجو. مشخصات سیستم با `--sysinfo` یا در انتهای `--benchmark` چاپ می‌شود.

## مدل‌سازی
* **حالت**: (موقعیت توپ، مجموعه‌ی الماس‌های جمع‌شده) → یک عدد صحیح `mask*W*H+pos`
* **کنش**: ۸ جهت؛ توپ می‌لغزد تا دیوار/لبه یا ایستگاه. برخورد با مین = کنش نامعتبر (هرس می‌شود)؛ حرکتِ بی‌جابه‌جایی هم نامعتبر است.
* **هزینه**: ۱ برای هر حرکت (پیش‌فرض) یا تعداد خانه‌های پیموده‌شده (`--cost cells`)
* **هدف**: همه‌ی الماس‌ها جمع شده باشند.
* **پیش‌تحلیل دقیق**: اگر الماسی از هیچ موقعیت دست‌یافتنی قابل جمع‌آوری نباشد، بی‌درنگ «بدون راه‌حل» اعلام می‌شود (`--no-precheck` برای غیرفعال‌کردن).

## الگوریتم‌ها
ناآگاهانه: `bfs` `ucs` `dfs` `dls` `ids` `ils` — آگاهانه: `astar` (`--weight >1` برای نسخه‌ی سریع‌تر ولی غیربهینه).
هیوریستیک A*: بزرگ‌ترین مجموعه‌ی الماس‌های باقی‌مانده که دو‌به‌دو **هم‌خط نیستند** (نه هم‌ردیف، نه هم‌ستون، نه هم‌قطر)، محاسبه‌ی **دقیق** → *قابل‌قبول و سازگار* (اثبات در گزارش).
`--tt` جدول انتقال (transposition table) به DLS/IDS/ILS اضافه می‌کند: گره‌ی کمتر، حافظه‌ی بیشتر.

## محدودیت‌های منابع
`--time-limit` (ثانیه، پیش‌فرض ۶۰)، `--max-nodes` (۵ میلیون)، `--max-stored` (۳ میلیون) برای هر الگوریتم. پس از رسیدن به هرکدام وضعیت `LIMIT` گزارش می‌شود.

## فرض‌ها
* خانه‌ی شروع یک ایستگاه (stop) در نظر گرفته می‌شود (مطابق منبع Tatham). اگر بازی شما غیر از این رفتار کرد: `--no-start-stop`.
* حرکت قطری از بین دو دیوار مجاز است (مثل بازی اصلی).
